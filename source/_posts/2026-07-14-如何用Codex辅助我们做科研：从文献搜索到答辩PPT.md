你开始用Codex了吗？

如果没有，那就今天。相信它可以让你科研的效果翻很多倍。

本篇内容我们就从研究生最常见的几个任务讲起：论文搜索、综述写作、数据分析、答辩 PPT，看看Codex是如何辅助科研的。

<!--more-->

### 01｜第一步：不要只把 Codex 当聊天机器人

很多同学不知道Chatgpt和Codex的区别。大白话解释一下，Chatgpt是「你问我答」，而Codex是一个Agent，「你说，我执行」。

我更建议大家把 Codex 当成“任务型 Agent”来用。一个具体任务建一个小文件夹。

比如你现在要做文献搜索，就建一个文件夹：

```
literature-search/
├── AGENTS.md
├── topic.md
├── seed-papers.md
├── search-results/
└── notes/
```

如果你现在要做数据分析，就建另一个文件夹：

```
data-analysis/
├── AGENTS.md
├── data.csv
├── variable-dictionary.md
├── scripts/
├── figures/
└── reports/
```

这里最重要的是 `AGENTS.md`。它可以理解成你写给 Codex 的任务规则。

一个文献搜索任务里的 `AGENTS.md` 可以这样写：

```
这是一个文献搜索任务。

研究主题：生成式 AI 对研究生科研自我效能的影响。

规则：
1. 不要凭模型记忆编造论文。
2. 所有推荐文献必须提供标题、作者、年份、来源、DOI 或可访问链接。
3. 先生成检索式，再执行检索，再整理结果。
4. 输出结果保存到 search-results/ 文件夹。
5. 不确定的信息请标记为“待核查”，不要写成确定结论。
```

一个数据分析任务里的 `AGENTS.md` 可以这样写：

```
这是一个问卷数据分析任务。

数据文件：data.csv
变量说明：variable-dictionary.md

规则：
1. 所有统计结果必须来自 data.csv。
2. 所有图表必须由 Python 或 R 代码生成，不要用图片生成模型直接画统计图。
3. 每一步分析都要保留代码。
4. 输出 data_quality_report.md、analysis_report.md、figures/ 和 scripts/analysis.py。
5. 如果变量不适合做某种统计分析，请先说明原因，不要硬做。
```

这样做以后，你给 Codex 的第一条指令就不是“帮我做科研”，而是：

```
请先阅读当前文件夹和 AGENTS.md，告诉我你理解到的任务目标、已有材料、缺失材料，以及下一步你建议执行的操作。先不要直接生成最终结果。
```

这一步很关键。它会让 Codex 先进入任务上下文，而不是直接开始自由发挥。

### 02｜第二步：Skill 不是提示词，而是成熟 SOP

Codex 里很重要的一个东西叫 Skill。

我对 Skill 的理解很简单：它不是一句提示词，而是一套成熟 SOP。

**提示词解决的是“这一次我怎么问 AI”。Skill 解决的是“以后每一次遇到类似任务，Agent 都应该按什么流程做”。一个好的 Skill 里通常会写清楚：什么时候使用、需要什么输入、应该按什么步骤执行、能调用哪些脚本、最后输出什么结果、哪些事情不能做。**

这也是为什么同一个 Codex，如果配置了不同 Skill，能力会差很多。没有 Skill 的时候，它更多依赖模型自己的通用能力；配置了合适 Skill 以后，它会沿着一个更稳定的流程干活。

但是这里一定要提醒大家：**不要因为一个 Skill 很火，就直接拿来写自己的论文。**

比如现在 K-Dense 的 Scientific Agent Skills 很受关注。它的 GitHub README 显示，这个仓库包含 148 个科学和研究 Skill，覆盖癌症基因组学、药物靶点结合、分子动力学、RNA velocity、地理空间科学、时间序列预测、科学数据库等很多方向。它当然很强，但从领域上看，里面大量内容更偏生物、化学、医学、组学、药物发现和科学计算。

这就意味着，**如果你是教育学、新闻传播、管理学、社会学，或者做计算机论文写作，你不能只看“这个 Skill 很火”。你要看它的工作流是不是适合你的研究任务。**

我建议大家安装任何 Skill 以后，先不要急着让它干活，先让 Codex 读一遍这个 Skill 的流程。

可以直接复制这段：

```
请先不要执行任务。请阅读这个 Skill 的 SKILL.md，并用中文总结：
1. 这个 Skill 适合解决什么问题？
2. 它需要我提供哪些输入材料？
3. 它会调用哪些脚本、工具或外部服务？
4. 它最终会输出哪些文件或结果？
5. 它明确不适合做什么？
6. 结合我的研究任务，你认为这个 Skill 是否适配？如果不适配，需要改哪些规则？
```

**如果 Codex 总结完以后，你发现这个 Skill 的默认流程和你的学科不匹配，不要硬用。你可以让 Codex 基于这个 Skill 修改一版更适合自己的流程，也可以把自己实验室经常使用的流程沉淀成自己的 Skill。**

举个例子，老师们经常有一套固定的论文终稿检查流程：查数值、查图表编号、查参考文献、查统计符号、查格式、查基金号。这种流程就非常适合写成 Skill。以后每次终稿前，不用重新写一堆提示词，直接让 Codex 调用这个 Skill 就可以。

### 03｜论文搜索：先生成检索路径，再让 Codex 真实检索

论文搜索这一步，最容易犯的错误是直接问 AI：

```
请推荐 20 篇关于生成式 AI 和研究生科研能力的论文。
```

这个问法很危险。因为它可能会凭模型记忆给你列一批看起来很像真的文献，但你不知道它到底有没有真实检索，也不知道有没有 DOI、PMID、数据库链接。

更好的做法是：先让 Codex 拆主题，再生成检索式，再用 Skill 或脚本真实检索，最后整理文献表。

比如我们的主题是：

```
生成式 AI 对研究生科研自我效能的影响
```

第一步，可以先让 Codex 生成概念矩阵：

```
请把下面这个研究主题拆成文献检索概念矩阵：

主题：生成式 AI 对研究生科研自我效能的影响。

请输出：
1. 核心概念
2. 英文关键词
3. 同义词或近义表达
4. 可能相关理论
5. 可用于 Google Scholar 的英文检索式
6. 可用于中文数据库的中文检索式

注意：这一步只生成检索语言，不要推荐具体论文。
```

它可能会拆出这样的检索入口：

| 概念| 英文表达| 可能扩展|
| ---| ---| ---|
| 生成式 AI| generative AI, ChatGPT, large language models| AI tools, GenAI, LLMs|
| 研究生| graduate students, postgraduate students| doctoral students, master students|
| 科研自我效能| research self-efficacy| academic self-efficacy, research confidence|
| 科研训练| research training| academic writing, literature review, research productivity|
| 技术接受| technology acceptance| perceived usefulness, perceived ease of use|

第二步，再让 Codex 生成检索式：

```
请基于上面的概念矩阵，生成 10 组 Google Scholar 检索式。
要求：
1. 不要只生成一条特别长的检索式。
2. 每组检索式聚焦一个角度，比如科研写作、文献综述、研究自我效能、技术接受。
3. 每组检索式后解释它主要想找到哪类论文。
4. 输出到 search-results/search-queries.md。
```

如果你是社科、教育学、管理学方向，可以用 Google Scholar 类 Skill 或其他真实检索工具去执行这批检索式。比如 ClawHub 上有 Google Scholar Search Skill，可以按关键词、作者、年份等条件检索，并导出元数据。使用时可以这样给 Codex 下指令：

```
请使用 Google Scholar Search Skill，基于 search-results/search-queries.md 里的 10 组检索式进行检索。

要求：
1. 每组检索式返回前 10 篇结果。
2. 合并去重。
3. 保留标题、作者、年份、来源、引用数、链接。
4. 初步判断主题相关性。
5. 输出 literature_search_results.md 和 literature_matrix.csv。
```

如果你是医学、生物医学或公共卫生方向，可以用我之前开源的 `pubmed-paper-finder`。它不是让 AI 编文献，而是让 Agent 把一个医学主题拆成多个 PubMed 检索模块，调用 NCBI E-utilities 获取 PMID、标题、期刊、年份、DOI、摘要、PubMed 链接，再按相关性、证据类型和新近程度生成候选阅读清单。

安装可以让 Codex 直接帮你做：

```
请帮我从 GitHub 安装这个 Skill：
https://github.com/yilaai/pubmed-paper-finder

安装后请先阅读 SKILL.md，告诉我它的检索流程、输入要求、输出格式和使用限制。
```

如果你已经有一批论文列表，还可以接上另一个 Skill：`paper-quality-filter`。这个 Skill 的作用不是判断一篇论文“学术价值高不高”，而是根据来源层面的证据给出阅读优先级，比如 JCR 分区、影响因子、中科院分区、CCF 会议等级、EI 收录、北大核心、CSSCI、AMI 核心、科技核心等。

安装方式费简单，你直接告诉codex：帮我安装某某skill，地址是***。

这一节最重要的原则是：**论文搜索不是让 AI 凭空推荐论文，而是让 Codex 帮你设计检索路径、执行真实检索、整理可核查结果。**

### 04｜综述写作：AI 很适合做阅读理解，但必须基于真实论文

我一直觉得，文献综述是最适合 AI 辅助的论文环节之一。

原因很简单：综述写作本来就需要大量阅读、归纳、比较、分类。AI 很擅长做阅读理解，也很擅长把一堆材料整理成主题矩阵。

但这里有一个前提：**必须基于真实论文。**

不要直接问：

```
请帮我写一篇关于生成式 AI 与研究生科研能力的文献综述。
```

更好的做法是先准备一个综述写作文件夹：

```
literature-review/
├── AGENTS.md
├── papers/
├── literature_matrix.csv
├── notes/
└── draft/
```

`AGENTS.md` 可以这样写：

```
这是一个文献综述写作任务。

规则：
1. 综述只能基于 papers/ 文件夹中的 PDF、literature_matrix.csv 和 notes/ 中的读书笔记。
2. 不得新增我没有提供或没有真实检索到的文献。
3. 每个重要观点后面必须标注文献来源。
4. 如果某个观点缺少文献支撑，请写入 unchecked_claims.md。
5. 先生成主题矩阵和综述大纲，再写正文。
```

然后可以让 Codex 先做文献矩阵：

```
请阅读 papers/ 文件夹中的论文和 literature_matrix.csv。

先不要写综述正文，请先输出 literature_theme_matrix.md，表格包括：
1. 主题板块
2. 代表文献
3. 研究对象
4. 研究方法
5. 核心发现
6. 研究不足
7. 和我的研究问题有什么关系

注意：只能使用我提供的真实论文。不要新增文献。
```

这一步做完，再让 Codex 写综述大纲：

```
请基于 literature_theme_matrix.md 生成综述大纲。

要求：
1. 不要按“张三说、李四说、王五说”排列。
2. 按研究主题和问题逻辑组织。
3. 每一节说明：这一节回答什么问题、使用哪些文献、最后要引出什么研究不足。
4. 输出 review_outline.md。
```

最后再写正文：

```
请基于 review_outline.md 和 literature_theme_matrix.md 写 literature review 初稿。

要求：
1. 每段都要有明确中心句。
2. 每个重要判断都要标注对应文献。
3. 不要写没有来源支撑的泛泛评价。
4. 不确定的地方写入 unchecked_claims.md。
5. 输出 draft/literature_review_v1.md。
```

如果你想借助现成论文写作 Skill，可以参考 `Research-Paper-Writing-Skills`。这个仓库主要面向 ML/CV/NLP 论文写作，包含 Abstract、Introduction、Method、Experiments、Conclusion 等部分的写作和自查流程，也适合用来做 claim-evidence alignment 和投稿前自审。

这里我想强调一句：**综述写作最怕的不是 AI 不会总结，而是它总结了不存在的文献。**

所以一定要让 Codex 先读真实论文、先做矩阵、先写大纲，最后再写正文。顺序不能反。

### 05｜数据分析：让 Codex 写代码跑结果，不要让大模型直接画图

数据分析是 Codex 特别适合参与的一个环节。

很多学生不是不想分析数据，而是卡在技术门槛上：R 不熟，Python 不熟，SPSS 点来点去又怕点错。尤其是问卷数据、实验数据、访谈编码表，真正麻烦的不是“讲道理”，而是清洗变量、检查缺失值、跑统计、导出表格、画图、写报告。

Codex 的优势是，它可以写代码、运行代码、看到报错、修改代码，再把结果保存下来。

但这里一定要有一个底线：**数据分析结果必须通过代码和真实数据生成，不能让大模型凭空生成统计图。**

比如我们有一份模拟问卷数据：

| 变量名| 含义|
| ---| ---|
| ai\_use\_frequency| 研究生使用 AI 工具的频率|
| research\_self\_efficacy| 科研自我效能|
| writing\_anxiety| 学术写作焦虑|
| literature\_skill| 文献阅读能力|
| grade| 年级|
| discipline| 学科|

文件夹可以这样建：

```
data-analysis/
├── AGENTS.md
├── data.csv
├── variable-dictionary.md
├── scripts/
├── figures/
└── reports/
```

第一条指令不要直接让它“分析结果”，而是先做数据体检：

```
请读取 data.csv 和 variable-dictionary.md。

先不要做统计推断，请先完成数据质量检查：
1. 样本量是多少？
2. 每个变量的数据类型是什么？
3. 每个变量缺失值比例是多少？
4. 是否存在明显异常值？
5. 量表变量的取值范围是否符合变量说明？
6. 输出 reports/data_quality_report.md。
```

第二步，再让它生成分析计划：

```
请基于数据质量检查结果，生成一个适合这份问卷数据的分析计划。

要求：
1. 先做描述性统计。
2. 再做相关分析。
3. 如果变量条件允许，做回归分析。
4. 每一种分析都说明使用原因、变量选择和结果解释边界。
5. 输出 reports/analysis_plan.md。
```

第三步，才让 Codex 写代码并运行：

```
请根据 reports/analysis_plan.md 写 Python 分析代码。

要求：
1. 使用 pandas、numpy、scipy、statsmodels、matplotlib 或 seaborn。
2. 所有分析结果必须来自 data.csv。
3. 保存完整代码到 scripts/analysis.py。
4. 输出 descriptive_statistics.xlsx、correlation_matrix.xlsx、regression_results.md。
5. 生成 figures/fig1_missing_values.png、figures/fig2_correlation_heatmap.png、figures/fig3_regression_coefficients.png。
6. 不要使用图片生成模型直接画统计图。
```

这样生成的图，才是可以追溯的。你可以打开 `scripts/analysis.py` 看它到底怎么算的，也可以检查 `correlation_matrix.xlsx` 和图是否一致。

如果你想用现成数据分析 Skill，可以参考 ClawHub 上的 Data Analyzer。它支持 Excel、CSV、Word、PDF、TXT、Markdown 等文件，可以做文件夹扫描、数据汇总、统计、趋势分析和报告输出。

安装方式：

```
openclaw skills install @tobewin/data-analyzer
```

安装后，我仍然建议先让 Codex 读 Skill 流程：

```
请先阅读 data-analyzer Skill 的 SKILL.md，告诉我它适合哪些数据分析任务，会读取哪些文件类型，会输出什么结果。然后结合我的 data.csv，判断它是否适合当前分析。
```

等基础图表生成以后，还可以用图表打磨类 Skill 做第二轮优化。比如你有 Nature Figure 类 Skill，就可以让它基于真实代码和真实数据优化图，而不是重新“想象”一张图。

例如：

```
请使用 $nature-figure，后端选择 Python。

请读取 scripts/analysis.py 和 figures/fig2_correlation_heatmap.png，基于同一个 data.csv 重新生成一版更适合论文或组会汇报的相关矩阵图。

要求：
1. 不改变任何统计结果。
2. 只优化配色、字体、标签、图例和导出格式。
3. 同时导出 PNG、SVG 和 PDF。
4. 输出 figures/fig2_correlation_heatmap_polished.svg 和 figures/figure_notes.md。
```

这里的逻辑一定要讲清楚：Codex 可以帮你写代码，可以帮你跑分析，可以帮你美化图表，但数据解释和统计方法选择仍然要由研究者判断。

### 06｜答辩 PPT：论文写好了，不要再手搓每一页

最后一个场景，是答辩 PPT。

很多同学论文写完以后，最崩溃的不是正文，而是把论文改成 PPT。论文是长文本，PPT 是现场表达。你不能把论文复制粘贴到 PPT 里，也不能每页塞一大段字。

论文到 PPT 的核心，不是“换个格式”，而是“重新组织答辩逻辑”。

我建议先建一个答辩 PPT 文件夹：

```
defense-ppt/
├── AGENTS.md
├── final-paper.md
├── figures/
├── tables/
└── ppt-output/
```

`AGENTS.md` 可以这样写：

```
这是一个硕士论文答辩 PPT 生成任务。

规则：
1. PPT 必须基于 final-paper.md 和 figures/ 中的真实图表。
2. 不要新增论文中没有的数据、结果和结论。
3. 先生成答辩大纲 outline.md，经我确认后再生成 PPT。
4. 每页只讲一个核心信息。
5. 同时生成 speech.md 作为逐页讲稿。
```

第一步，让 Codex 拆论文逻辑：

```
请阅读 final-paper.md。

先不要生成 PPT，请先输出 defense_logic.md，包括：
1. 这篇论文的研究问题是什么？
2. 为什么这个问题值得研究？
3. 文献综述最后引出了什么不足？
4. 本文的方法设计是什么？
5. 主要发现是什么？
6. 创新点是什么？
7. 答辩时最可能被问到的问题有哪些？
```

第二步，让它生成 PPT 大纲：

```
请基于 defense_logic.md 生成 12 页左右的硕士论文答辩 PPT 大纲。

要求：
1. 每页包括：页标题、核心信息、建议图表、讲述重点。
2. 结构包括：研究背景、研究问题、文献基础、研究方法、主要发现、创新点、不足与展望。
3. 不要直接生成 PPT，先输出 outline.md 等我确认。
```

第三步，再使用 PPT Skill。

比如 `codex-ppt-skill` 可以把文章、报告、论文、课程笔记、Markdown、PDF、Word 等材料转换成图片式 PPT。它的流程不是直接一口气生成完，而是先规划大纲和视觉风格，生成样张确认，再逐页生成幻灯片图片，最后组装成 `.pptx`。它还会生成 `speech.md`，并写入 PPT 每页备注。

安装方式：

```
npx -y skills@latest add ningzimu/codex-ppt-skill \
  --skill codex-ppt \
  --agent codex \
  --global
```

使用时可以这样写：

```
请使用 codex-ppt skill，把 defense-ppt/final-paper.md 做成 12 页左右的硕士论文答辩 PPT。

要求：
1. 先阅读 AGENTS.md、defense_logic.md 和 outline.md。
2. 如果 outline.md 还不适合答辩，请先提出修改建议，不要直接生成 PPT。
3. PPT 使用科研答辩风，页面简洁，减少大段文字。
4. 必须保留论文中的关键图表，不要编造新数据。
5. 生成 outline.md、speech.md 和最终 .pptx。
6. 每页备注区写入对应讲稿。
```

这里也要提醒大家：`codex-ppt-skill` 主要生成的是整页图片式 PPT，优点是视觉统一、速度快，适合快速把论文变成可讲的答辩稿；缺点是页面元素本身不一定能像普通 PPT 那样逐个编辑。如果你后面还要精修，可以继续用可编辑 PPT 转换类工具，或者在 PowerPoint 里手动调整关键页。
